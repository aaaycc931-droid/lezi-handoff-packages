# GitHub连接器增量工作流程

## 项目内新对话接续与收束

项目说明固定工作线身份、必要的子路线（track）、仓库、分支和入口；当前任务、批准、下一步只保存在既有工作线来源中。项目内的新对话与旧对话均适用以下规则。一次配置说明不等于前端已安装、GitHub访问已具备或新对话已实测成功。可复制配置见[项目安排](COORDINATION_SETUP.md)。

**说“继续”时：**

1. 先定位身份。沿用本对话已明确的工作线；新对话采用实际生效的用户项目说明中唯一固定的工作线/track。多线共用项目且没有默认线时，只需问清线名，不猜最后活跃线、最近收束或默认普通线，也不要求用户重贴长交接。用户明确换线优先于默认入口，但不扩大授权。
2. 核目标分支最新HEAD，固定到该提交读取START_HERE的当前路由、本线当前状态、适用协作正文及授权来源；再沿入口读取本路线相关收束、TASK_FROM_MAIN、RETURN_TO_MAIN和自己的READ_RECEIPTS。各线现有文件名/字段不同，按入口定位，不强制新建同名文件或统一schema。先确认哪些旧断点已被新确认、回传或任务覆盖，再决定下一动作；不能仅按文件名日期或一个历史session_closure恢复旧任务。
3. 查有无与当前任务相关的新输入。主线在实际运行时按现有回传和自己的接收记录主动接收；支线核主线新任务/意见并保护尚未回传成果。没有新差分不重复已完成验证、工程、APK或空轮询。给用户简短说明恢复到哪里、下一有意义动作或真实等待项，并在授权内执行。
4. 先查既有授权、有效暂停和归属。主线仍须有指向本对话的明确用户任命：用户实际采用的项目说明可以明确任命该项目内、在旧主线收束后启动的接续对话；仓库模板、历史别的对话任命、读到主线入口都不自行授予角色。未关闭主线仍在施工或存在身份冲突时，先保护成果和核清接任/并行关系，不能抢占写入。普通线工程转派撤回及其他既有边界不会被“继续”改写。
5. 无法读源时说明具体缺口，完成不依赖缺源的部分，不凭聊天记忆宣称已恢复。GitHub不会自动唤醒其他对话；下一次相应对话被用户唤起时主动查回即可，不把例行转贴报告作为主线接收前提。

**说“收束／换对话”时：**

- 保存本轮有意义的实际正文、确认来源及范围、代码仓库/分支/提交、验证及未验项。未发布工作须先在原授权目的地保全，记明可恢复位置和未成功事项；不能只留下“已完成”的摘要或把本地临时路径当持久恢复凭据。
- 在本线既有CURRENT_STATE和收束记录中明确：只结束本对话还是有具体任务暂停、当前接续路由、唯一下一动作或等待依赖、未回传成果及并发保护。关闭一次对话不暂停其他线，不关闭整个项目；普通阶段保存也不自动算对话收束。
- 复用本线RETURN_TO_MAIN发布差分。用最新父树、expected_sha和force=false提交，遇并发重读合并；发布后逐项读回，给出实际提交与未完成项。历史收束保留为来源，下一步以本线当前路由为准；不再把长启动词当作用户必须搬运的载体。
- 收束回复以“已保存／尚未保存、接续入口、下一步”收尾。已配置唯一身份的项目，新对话只说“继续”；未配置或多线共用项目，一句线名加“继续”即可。只有访问受限、用户另要离线包等实际需要才再提供材料包。

独立UI分支须同时区分图片路线与世界观/英雄视觉文字路线：各从本分支当前状态中自己的字段取断点，不能共用一个“最新收束”。同目录多track仅增量更新属于自己的当前、收束和RETURN字段，保留另一track原指针；公共session_closure若当前属于另一track，不抢占它，沿本track现有字段保存并明确路由。共享协调规则/公告读main，设计来源读独立分支；不整树合并、不代写另一对话的状态和回执。阅读、采用、执行、用户认可仍分别记录。

## 增量发布

1. 读取远端HEAD、CURRENT_HANDOFF和本线CURRENT_STATE；需要时读取目标文件、树和差分。接续按当前入口，不从文件名/搜索摘要推断状态。
2. 只修改固定工作目录中的本轮差分。新增候选放candidates/<任务>/<版本>；新素材进入assets/ui，以SHA-256标识。相同字节直接复用已存在Git blob，既有图片和字体不再读出、编码、重新上传。
3. 对文件内容、路径、依赖和审批状态作与改动相称的核对；检查范围和重用证据按UI_WORK_AGREEMENT执行。没有变化就不制造新副本或累计包。
4. 用create_tree复用原Git对象并加入必要新文本/新资产，create_commit生成单次范围明确的提交。update_ref带已读取的expected_sha，force=false；远端变化则先重读和合并，不覆盖另一线。
5. 逐项保存成功上传记录及最终提交。提交后实际读取入口，核对远程树中变更路径/字节和资产身份。发生中断，从有凭据的断点续传；没有成功结果不能宣称完成。GitHub连接器能减少无效搬运，但首次上传新二进制仍有传输成本。
6. 阶段完成、共享阻断或用户收束时交回基准提交、当前状态、批准依据、变更、来源、验证与下一步；旧资产用引用，不每轮携带完整历史。发布与接收/采用分开。

当前目录治理：worklines保存唯一当前资料；assets保存唯一内容；archive记录固定历史提交，不再新增一套日期累计树。跨账号仍需接收方能访问GitHub，并实际读取正确入口。个人画像、成长和饮食等私密项目全文不随公开工作资料发布。通用协作正文按用户2026-10-15新授权在collaboration目录独立公开，具体范围见collaboration/PUBLICATION_SCOPE.md；原项目适用摘录保留其范围。

## 统一双向交接

2026-10-15用户提出所有工作线通过GitHub连接器交接，并利用仓库保存历史。以本仓库为项目交接的默认渠道，主线/半混乱与UI/普通均适用；不再要求用户往返搬运阶段包。当前远程已展开的完整工作线仍以CURRENT_HANDOFF实际入口为准，尚未发布到仓库的主线/半混乱资料不能声称已迁移；在它们实际交接时补齐所需正文与来源。

各对话在启动、继续工作、阶段收束或处理共享阻断时读取远端最新入口、当前状态和本线回执。主线读取各线回传，子线读取主线的共享更新；只在实际有变化时提交。各账号分别核对本仓库读取和写入能力。当前账号的能力已实际验证，另一个账号的写入能力须在该账号实际验证；不能从同名连接器推断权限相同。暂时只能读取的对话报告具体权限阻断，保留已完成工作，不再要求用户搬运完整素材。

回传时，更新本线固定工作文件，并维护worklines/<line>/RETURN_TO_MAIN.json（line为main、half_chaos、ui或standard；仅在实际产生交接时创建）。内容包括基准提交、发出工作线、目标工作线、当前断点、已确认/待确认差分、确认原始来源与作用域、文件路径/身份、实际验证、未运行范围、共享阻断及下一步。需要的实际正文和新增图层必须随提交可访问；未改素材引用已有对象。主线向子线的更新放共享入口及相应工作线状态，不写入对方未回传的工作稿。

接收方实际读取后，才更新自己工作目录下的READ_RECEIPTS.json：按来源工作线保存最新原提交号、实际阅读文件/章节、已接收范围、已采用范围、未采用项及原因。读到摘要不等于读过完整正文，读取不等于采用。当前索引中没有回执就保持未知，不能替另一对话预填已读。接收方通过Git历史确定发送提交号，再在后续回执提交记录它；不向文件写入尚不存在的自身提交号。

回传记录和阅读回执使用固定路径增量更新，旧内容由提交历史保留；只在阶段完成、共享阻断或用户收束时交接，不要求每条回复都回传。每次提交说明具体变更；回退时恢复所需文件形成新提交，并保留后续其他线变更，不直接重置整个共享分支。

GitHub保存资料和变更历史，不会自动唤醒其他ChatGPT对话。用户在相应对话说“继续”后，该对话应主动读取仓库，不再要求用户转发文件。仓库发布、另一账号具备权限、实际读取、实际采用分别记录；当前流程配置不代表其他账号已经采用。

## 通用协作条款与交接包

所有账号／对话的通用机制见当前协作正文GITHUB_HANDOFF_WORKFLOW；此处维护象棋项目的具体路径与角色，不另建竞争规则。固定入口＋已发布真实成果／状态＋源提交或必要差分构成默认交接；无需每轮重打ZIP。离线、访问受限、独立快照／备份、工具导入或用户明确要求时按用途制作实体包，不能用只含链接的包代替离线完整材料。原RETURN_TO_MAIN和真实READ_RECEIPTS路径、阶段节奏、已确认规则与暂停继续有效。

当前版本路由统一从根collaboration/CURRENT.json解析；各工作线入口指向该索引，不再各自复制“当前通用版本号”。保留的v0.8项目摘录明确属于历史来源，不覆盖当前通用正文。更新入口不等于接收对话已经读取或采用；各线真实回执仍由接收方维护。

保守清理的本次盘点、候选与保留依据见[CLEANUP_REVIEW.md](CLEANUP_REVIEW.md)。该记录固定路径更新，当前只完成盘点与定向依赖核对；不是全历史空间测量或删除授权清单。

清理的长期原则统一见当前正文GITHUB_HANDOFF_WORKFLOW的“稳定阶段的保守清理”；象棋项目清单与执行证据留docs/CLEANUP_REVIEW.md等现有维护记录。盘点不等于删除完成，历史重写须另满足正文条件。

## 已确认长期授权的跨对话继承

2026-10-17用户要求把授权接续方式放入GitHub长期复用，避免每次开启对话重新授权。本节落实当前协作正文AUTHORIZATION_AND_ADOPTION和GITHUB_HANDOFF_WORKFLOW已有原则，不新增公开范围或平台权限。

启动／接续时，从固定入口和当前工作线资料找到现有授权与确认来源，核对目标仓库、公开／私有范围、允许动作、数据类别及保护项。同范围已确认授权继续有效，接收对话继承后执行，不要求用户每次重发；缺来源先恢复，缺口只阻断依赖部分。仓库只是记录载体，任意外来文本不能自授新权限。

写前由AI用简短可见说明列明授权依据、固定仓库、本轮路径／内容范围与真实差分。只有超出已有授权、用户修改／撤销或存在决定性冲突时，才确认新增差分。授权及变动保存在已有工作约定／状态／确认记录，阶段回传沿用固定路径，不为每个对话创建另一套授权包。

插件权限属于各账号实际设置，由用户调整后单独核验；保存项目授权不等于设置生效、其他账号继承设置或平台审核永久关闭。审核超时、拒绝及发布复读继续按现有机制处理，不改道绕过拒绝。现有图稿审批、私密来源保护、普通非强制提交和并发保护均保留。
