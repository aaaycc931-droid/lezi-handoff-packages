## 4. 失败分支：有临时死亡，但没有可提交完整重演

重演讳言目标改为红仕4、红仕6、**红中央兵**、红马8。四枚都在合法敌方明置非将帅池中。红兵移除后，红车沿(5,4)到(5,10)直接将军。

原黑马只能从(2,10)行动，无法到第5列挡车，也无法吃红车。脚本对90个棋盘目标调用局部合法走棋检查，合法结果0：几何可达的马步也因黑将继续受将而拒绝。这里证明的是**H05要求的原行动棋无解**，不是“黑方所有棋都无解／已经将死”。H05不能改选黑将或其他棋来救场。

因此按已确认设计，整次候选不能成立。恢复到发动前旧黑7完成后的权威状态：旧线四枚死亡仍有效；候选中新死的红中央兵仍存活于旧线(5,7)，候选里暂时复原的旧红马2不能被留在正式棋盘。

| 数据 | 失败后的来源要求 |
|---|---|
| 棋盘、英雄状态、降临结果、当前死亡列表 | 回到发动前旧线，不能留下候选分支的一部分 |
| 已接受旧死亡审计、原重置段及计数 | 保留，不倒回黑7开始前 |
| 候选死亡与候选重置／采样 | 不进入已接受账本；可留内部失败诊断，但不得计成正式事件或泄露秘密 |
| H05整局使用次数、成功占步 | 不扣次数，不建立成功占步记录 |
| 本回合正式尝试标记 | 保留已尝试，本红8不得重试 |
| 同锚点已锁随机结果 | 按既有防试探规则保留，不因回滚棋盘重新抽取 |
| 红8后续流程 | 回到正常begin／行动；不是跳过红8，也不是整局免费多一回合 |

**关键工程风险**：若先把候选死亡写入不可倒退的外置账本，再靠回滚棋盘处理失败，就会留下虚假的重置／死亡。反过来，一次失败把整个外置账本回退到历史快照，也会抹掉已接受旧死亡。正确隔离需要同时保住旧接受记录和本次尝试／锁随机，丢弃未接受候选；该合同尚未在生产实现中验证。

## 5. 合法不利分支及其未覆盖部分

该例支持：正式发动后看见begin重抽不利，也不能主动取消；若完成合法重演并成功提交，必须正常消耗H05并登记占步，保存旧执行审计与新执行事实。多个审计版本不是多个原黑7正式回合；审计条数也不等于重置调用次数。
