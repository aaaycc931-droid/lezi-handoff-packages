## 1. 用户请求与已确认边界
- 本轮此前已暂定视觉方向：高反差动态泼墨＋写意人物＋冬季武侠（见 `VISUAL_STYLE_DIRECTION_HANDOFF_20261101.md` 第10节），墨浪、剑的强透视及构图动势应保持。
- 用户从一组**同构图的出剑画像**中表示喜欢其中一张，并指出其**脸部和手部过于真实、娇嫩，眼和嘴唇的刻画与全画水墨风格割裂**。
- 用户提供此前一组 **A/B/C/D 四画面参考**，明确**只借鉴四张的冷峻、硬朗、简练墨线/留白处理的面部表情与笔法**；不是要求重画这四张，也不是借鉴它们的整张构图或斗笠。
- 正确任务：**固定用户选中的那张出剑目标图，以原图为基线，在确定的面部、必要时手部局部范围内作写意化处理，保护其余区域**。用户当前并未确认任何本轮局部修复版本。
- **精确底图身份尚未核验**：当前会话有用户截图、生成图与对照，尚未在仓库登记「选中的目标图」的原始 PNG SHA/独立可读资产及A/B/C/D的独立来源身份。截屏与浏览缩略图不能被冒充为无损母版。修复前必须找回并固定准确底图和对照来源。

## 2. 已观察到的执行偏差
1. 在只应修改目标图脸部与手部时，AI先对**作为参考的四张图**重新生成一个四宫格比较板，改变了参考图形象；被用户明确指出违反任务对象。
2. 用户纠正后，AI仍以「整幅生成」方式制作出剑画，出现**斗笠、人物形象、构图和部分环境**等超出请求的变化；第二次尝试仍保留/新增斗笠，未能锁定原始目标图。
3. 未将目标图完整源文件固定为不可变母版；未建立脸/手允许修改蒙版与其他保护区；未执行区域外像素差分核验、图层合成或候选与底图身份检查。
4. AI事后解释过「局部编辑/原图合成」方法，但在失败迭代时**没有真正执行或验证**；不能把文字承诺算作修复。
5. 用户反馈（原话节选）：「这组参考图跟屎一样，太难看了，你在乱改吗」「我让你以这4张图的表情修改我要修改的图片，结果你反过来把这4张的重新加工了」。应按此判断任务执行失败，不能将错误图标记为通过或有效候选。

## 4. 已证实 vs 待调查
**已证实**：连续整图重绘导致对象错置、非目标元素改变；未见完成局部掩膜、精确底图核验、受保护区像素对比或真正源层合成的证据；输出被用户否决。修复尚未完成。

**尚未证实**：图像生成工具是否支持满足本图的精确局部保真；失误发生的模型内部原因、指令是否在生成链条中特定阶段丢失、具体调用接口可达到的编辑精度；不能凭现象断言系统平台原因或承诺自动解决。

**影响范围**：本次视觉探索会话与新增无效图像；未观察到它们被批准登记采用、合并游戏源代码或替换既有 B1—B9 审批资产。B10-v1仍待审；评分冻结、NET暂停，主线接收/采用状态保持未知。

## 5. 修复行动与验收闸门
1. **暂停该目标图的整图再生成**，所有上一轮错误对照板/斗笠出剑图标为 rejected / not-approved，不能覆盖用户选中的目标与四张参考。
2. **恢复证据/身份**：找到用户选择的原始无损出剑图、其准确尺寸与 SHA-256；恢复四张原始 A/B/C/D 参考，仅将它们作为脸部笔法/表情参照；必要时先核对用户截图对应哪一个实际原始文件，不能凭相似构图猜选中图。
3. **局部变更约束**：生成只允许的面部区域蒙版（必要时手部另起一轮），定义明确冻结区——斗笠不得擅自新增、头发、剑、动作、服饰、红梅、远山、建筑、墨浪和构图都不因修脸而重绘。记录图层与参数。
4. **方法选择**：优先真实的蒙版式局部编辑或独立源层绘制，局部合成回**原图字节解码的画面**；对区域外计算像素差分，应为0，展示裁切细节、修订前后对照以及区域外保护检查的事实结果。若工具不支持或无法实际核验，立即报告受阻，提出手工/专业分层编辑替代，不可再次冒充完成。
5. **顺序**：先修脸并由用户审阅一张真实结果，再另轮修手；保持“脸的硬朗结构、墨块阴影、简约眼唇、无皮肤肉感”和“原始泼墨爆发力”的双重标准。
6. **验收边界**：像素保护通过≠用户审美满意。仅经用户具体确认才能更新候选采用/审批；未运行验证不可标通过。新素材需有可取得的原文件/参数/校验身份；跨账号实际接收与采用由接收方自己填写。
