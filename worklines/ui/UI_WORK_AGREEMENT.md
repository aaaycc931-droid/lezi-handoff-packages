# UI专属工作约定

本约定依据用户2026-10-15关于UI包优化、利用GitHub连接器及整理仓库的明确要求，最初落实协作工作稿v0.8的项目方法适配；当前通用协作规则从../../START_COLLABORATION.md及../../collaboration/CURRENT.json定位，本约定继续控制UI专用方法与批准基线，不另复制当前通用版本号。范围是资产组织、读取、制作、检查和交接；不改游戏规则、通用协作主文件或审美基线。

## 读取与制作

日常只读固定入口、当前UI状态/审批及本任务完整依赖；需要某项历史或产品规则再加载其完整来源。清单/摘要不能代替实际图、源层和语义正文；缺源只阻断受影响部分。源文件内部pending属于生成时历史，当前根审批和SOURCE_STATUS_OVERRIDES优先。

延续固定批准母版＋全部批准差分＋独立源层＋真实字体＋局部合成。区分新候选探索、批准稿精修、资产提取和产品接入；不为减小包体压缩重编码图片、拉伸、提亮/锐化或整图重绘。历史背景估计限制照实保留，不逐轮补底。baseline仅作冻结来源，候选在work/另存；历史compose/finalize可能写源文件，只能在候选副本执行。旧稿允许蒙版不能直接当成新B6授权区域。

一次展示一张实际候选，用户明确审批后才更新批准指针。优化交接不是批准B6；不重开B5审批、不恢复H1/V4撤回稿，首页/V4原字体例外保留。

## 验证节奏

局部改动核对母版身份、真实修改区、保护区像素和实际视觉，并查直接状态/权限依赖。字节、条件和有效证据未变时复用；共享字体/背景/组件改变、来源冲突、意外像素变化或阶段交付，再扩大至受影响范围。不每改一行全量重跑所有页面或双机测试。

静态审批、源层重合成、视觉审美、交互/动效、设备字体/触控、蓝牙双机和产品接入分别记录，未运行不写通过。当前只整理流程与仓库，无图稿/游戏规则变化，评分冻结、NET暂停。

## 连接器与资产

先用GitHub连接器读远端HEAD、CURRENT_HANDOFF和文件树，按变更比较真实内容。现有素材以Git对象直接复用；相同SHA-256且Git内容身份一致只保留一份，通过别名恢复旧目录。新内容才上传，严禁每轮重新读出、编码、上传完整素材。大二进制首次上传仍可能受接口限制，连接器不会自动消除传输成本。

上传只形成一次范围明确的提交；更新分支时带已读取HEAD的乐观锁，发生并发变化先重读，不强制覆盖。逐项记录上传结果和最终提交，提交后核对路径/身份和实际入口；发布不等于接收对话已读或已采用。

**关键二进制资产交接完成闸门（2026-11-05 执行补强）**：只在现有资产/交接记录中逐项列出 `source_present`、`source_sha256_verified`、`remote_uploaded`、`remote_readback_verified`、`recipient_access_verified` 及对应实际证据；状态字段是执行结果，不是凭文件名推断。对要求跨账号交付的关键 PNG，缺任何远端原字节及读回证据即标 `partial_handoff_with_asset_blocker`，不得以 GitHub 文本提交或同账号 Library 保存宣告完整交接。先测二进制桥梁再提交大图；无法传输时保留原件、交付经哈希校验的离线包并记录手工/受权替代渠道与待验证动作，包本身不能冒充远端归档。隐私与公开范围在实际发布前单独核对。此处落实既有 `GITHUB_HANDOFF_WORKFLOW`，不重复另建通用规则。

## 维护和交接

固定worklines/ui为唯一当前工作目录；assets/ui为唯一共用素材体，旧轮次留Git历史固定提交索引，不继续堆日期版累计目录。新候选及新增源层放candidates/<任务ID>/<版本>，明确candidate/approved/withdrawn；未批准不覆盖定稿。只在需审批/交接时保留有价值证据，临时导出不提交。

阶段结束、共享阻断或用户收束时，回传基准提交、当前完整状态、确认原话/时间/作用域、新图与新增源层/参数、变更文件、实际验证和唯一下一步。未改资产引用其身份和固定来源；新依赖必须可访问。无需每轮累计ZIP，完整备份只在明确备份/恢复需求时生成。

主线账号维护共享协调/半混乱；另一个账号维护UI/普通。未收到的新UI对话成果保持未知，不擅自覆盖。此约定不保证未来模型自动执行，跨账号真实接续仍需其读取回执。

## 受控执行与阻断恢复

2026-10-16用户已确认并要求实施本轮流程优化。工具输出、二进制传输、授权证据、分阶段成功凭据及分类恢复，统一执行当前通用正文SOURCE_ACTIVATION与GITHUB_HANDOFF_WORKFLOW；本约定不重复维护这些定义。

UI制作按保护未回传成果→核对当前状态和本任务直接依赖→复用有效证据并补必要检查→展示一张实际候选→按阶段增量回传组织。上传受阻时已保存候选仍可查看；查看完成与回传完成分别记录。用户暂停或仅要求诊断／流程维护时，保持UI暂停。B6恢复成果先保留并对账，不用旧仓库“未创建”状态要求重新生成；图稿仍待具体审批。

保真、字体及许可、B5批准、首页／V4例外、撤回记录、评分冻结和NET暂停均沿用。执行顺序优化不批准候选、不替代运行验收。

单条会话失联、刷新后新消息消失时，执行当前通用正文GITHUB_HANDOFF_WORKFLOW的会话失联恢复，不依赖旧会话自行打包；保护较新具体批准及原图／源层，先核对真实写入。旧运行状态不明时，不能隔离写入范围则不并发修改同一对象；资料恢复不等于原会话恢复。

## 2026-11-04｜视觉多方案比较—用户选择—基准继承（UI 专属长期补充）
用户在本轮明确提出并认可：「你可以按不同的方向生成，然后我来看效果……作为我们的项目推进的一种规则让我来选吗」「最后一版不错，然后你可以根据这一版呢，再发展出几个方向，我们就这么做，这样就比较好」。这属于 **UI 视觉探索工作方法的明确约定**，并不授权改写通用协作正式正文或任何正式 UI 产品审批记录。

1. **抽象感受转为直观看图**：用户很难准确描述脸部五官、表情、笔墨气质等差别时，AI 主动选择若干真正有区分度的视觉方向，给出编号、可比对的真实图片，用户通过选择、排除、多选组合或指出局部问题表达偏好；不要求用户反复提供专业美术术语，不替用户作审美定稿。
2. **每轮只改变所讨论的变量**：确定当前唯一工作对象、已选参考母版、需要探索的局部（本例为脸／眼线或手／珠串）、不可变的其他画面与比较标准。优先固定人物、姿态、画幅、衣袍、剑透视、背景、色彩，避免用不同构图假装笔法比较。
3. **对比探索与保真编辑分开**：未定风格可显示 A/B/C/D 等多个 **探索选项** 或一张编号对比板，供一次选择；用户明确选择后，将选中版本连同原像素与来源单独保留。进入“仅修某处”的保真阶段，采用蒙版／独立局部图层和合成，以原图为不可变母版；**整图生成不得冒充只改脸或只改手**。本约定的多方案探索不改变既有正式 UI 图稿“逐张展示—逐张批准”的门槛。
4. **按用户选择逐层收敛**：保留喜欢的版本作为下一轮设计基准，再从该版本发展少量不同方向，而不是退回更早的 AI 方案或一次改变多项；用户说“喜欢/不错”作为正向候选偏好，“就定这个风格”只确认所指 **视觉风格方向**，不自动批准最终角色图、逐屏 UI 或游戏代码；“先保留”仅表示保存未审批候选。
5. **错图和阻断治理**：若参考图被误改、非目标区域变动或生成失控，立即标记为 rejected，复核真实源图并停止无控制重绘。技术验收（局部以外像素差分、尺寸、源身份）与视觉审美验收分开报告；技术通过不代替用户选择，原因不明不虚构根因。
6. **阶段性保真收束**：结束对话时写入 GitHub 唯一固定 UI 工作目录，保留确认原话与状态、选中母版／候选的准确身份、SHA-256、能否跨账号取得原始 PNG、图层与参数、审美修改边界、实际验证及唯一下一步，复读核对提交。GitHub 没有图片原字节时须明确写明缺口，不能只给文件名却说完整迁移成功。
7. **与主线/旧审批并行**：独立视觉讨论不改变 B1—B9 静态批准、B10 待审、首页/V4 例外、NET 暂停、评分冻结、引擎及跨线接收。主线统筹整个 UI 项目应用和发布；本项只负责风格探索及可审阅原型。

当前适用实例与精确源身份见 `worklines/ui/VISUAL_SESSION_CLOSEOUT_20261104.md`。本补充为 UI 专属规则增量；通用正文仍遵循 `START_COLLABORATION.md` → `collaboration/CURRENT.json` 指定的唯一作者来源和权限边界。
