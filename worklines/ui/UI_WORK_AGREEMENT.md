# UI专属工作约定

本约定依据用户2026-10-15关于UI包优化、利用GitHub连接器及整理仓库的明确要求，落实协作工作稿v0.8的项目方法适配。范围是资产组织、读取、制作、检查和交接；不改游戏规则、通用协作主文件或审美基线。

## 读取与制作

日常只读固定入口、当前UI状态/审批及本任务完整依赖；需要某项历史或产品规则再加载其完整来源。清单/摘要不能代替实际图、源层和语义正文；缺源只阻断受影响部分。源文件内部pending属于生成时历史，当前根审批和SOURCE_STATUS_OVERRIDES优先。

延续固定批准母版＋全部批准差分＋独立源层＋真实字体＋局部合成。区分新候选探索、批准稿精修、资产提取和产品接入；不为减小包体压缩重编码图片、拉伸、提亮/锐化或整图重绘。历史背景估计限制照实保留，不逐轮补底。baseline仅作冻结来源，候选在work/另存；历史compose/finalize可能写源文件，只能在候选副本执行。旧稿允许蒙版不能直接当成新B6授权区域。

一次展示一张实际候选，用户明确审批后才更新批准指针。优化交接不是批准B6；不重开B5审批、不恢复H1/V4撤回稿，首页/V4原字体例外保留。

## 验证节奏

局部改动核对母版身份、真实修改区、保护区像素和实际视觉，并查直接状态/权限依赖。字节、条件和有效证据未变时复用；共享字体/背景/组件改变、来源冲突、意外像素变化或阶段交付，再扩大至受影响范围。不每改一行全量重跑所有页面或双机测试。

静态审批、源层重合成、视觉审美、交互/动效、设备字体/触控、蓝牙双机和产品接入分别记录，未运行不写通过。当前只整理流程与仓库，无图稿/游戏规则变化，评分冻结、NET暂停。

## 连接器与资产

先用GitHub连接器读远端HEAD、CURRENT_HANDOFF和文件树，按变更比较真实内容。现有素材以Git对象直接复用；相同SHA-256且Git内容身份一致只保留一份，通过别名恢复旧目录。新内容才上传，严禁每轮重新读出、编码、上传完整素材。大二进制首次上传仍可能受接口限制，连接器不会自动消除传输成本。

上传只形成一次范围明确的提交；更新分支时带已读取HEAD的乐观锁，发生并发变化先重读，不强制覆盖。逐项记录上传结果和最终提交，提交后核对路径/身份和实际入口；发布不等于接收对话已读或已采用。

## 维护和交接

固定worklines/ui为唯一当前工作目录；assets/ui为唯一共用素材体，旧轮次留Git历史固定提交索引，不继续堆日期版累计目录。新候选及新增源层放candidates/<任务ID>/<版本>，明确candidate/approved/withdrawn；未批准不覆盖定稿。只在需审批/交接时保留有价值证据，临时导出不提交。

阶段结束、共享阻断或用户收束时，回传基准提交、当前完整状态、确认原话/时间/作用域、新图与新增源层/参数、变更文件、实际验证和唯一下一步。未改资产引用其身份和固定来源；新依赖必须可访问。无需每轮累计ZIP，完整备份只在明确备份/恢复需求时生成。

主线账号维护共享协调/半混乱；另一个账号维护UI/普通。未收到的新UI对话成果保持未知，不擅自覆盖。此约定不保证未来模型自动执行，跨账号真实接续仍需其读取回执。
