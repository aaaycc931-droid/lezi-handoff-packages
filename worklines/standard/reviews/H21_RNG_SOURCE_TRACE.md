## 1. 权威玩法确认与代码事实的区别

当前 `worklines/standard/rules/shared/02_CURRENT_HEROES.md#H21` 写明：无敌形态在真正降临时「随机选择最多4枚己方当前合法控制的非将/帅棋」，被选暗子先揭示，获得龙爪及一次龙鳞；预兆期间不提前锁定随机结果。普通模式的已确认继承见 `work/LEZI_STD_DESIGN_03_WORKING_20261014.md` 对应H21无敌章节（原展开版见 `sources/standard/LEZI_STD_DESIGN_03_WORKING_20261014.md`）。该已确认文字**没有显式规定**池≥4时必须抽4，亦未保证四子集合均匀概率、可用种子或日志重播；不能将代码行为直接登记成新玩法批准。

对照代码 `src/hero-descent.ts`（PR13参考提交、也存在相同旧固定源码）：

- L11–14 `choose(items,count,random)`：先复制候选池，循环 `pool.splice(random(pool.length),1)`，直到池空或结果达到 count。每步删除已选元素，因此**无放回**，抽中顺序由剩余数组索引与随机输出决定。
- L20–36 `ascendGalakrond`：在形态为 `invincible` 时，根据当前实际棋盘过滤 `isBoardPiece(p) && getController(p) === side && (p.faceDown || p.type !== "general")`；调用 `choose(pool,4,random)`，每个选中ID被揭示（若暗）并赋 `dragonClaw:true,dragonScale:1`。
- `src/spaces.ts`：`isBoardPiece` 排除河道，但不天然排除飞行层；普通模式固定全明，因此不需要把暗子揭示当成额外抽签。
- `src/settlement.ts` L301–337：新正式回合开始，在有预兆、未终局的路径进入 `ascendGalakrond(...,randomInt)`；抽签使用当时实时池而非B4提前预选。

**实现事实（非新增规则）**：池大小N为0时选0；N为1、2、3时分别选N；N≥4时恰选四。单个ID不重复。这让以前的「数量未知」从**代码层**改为已定位；但**规范层**仍为「最多4」，若未来强制把`min(4,N)`写入共享裁判规范，须核实原确认或按主线/用户批准处理，不在本线静默改义。

## 2. 随机源、概率与实际重放

`RandomInt` 是 `(maxExclusive:number)=>number`（`src/types.ts`）；`src/hero-actions.ts` L83–107 与 `src/settlement.ts` L301/345/369 中出现基于 `Math.floor(Math.random()*max)` 的默认 `RandomInt` 路径，并可由调用方传入随机函数；`src/setup.ts` L36–47 虽另提供 `crypto.getRandomValues` 与拒绝采样的 `secureRandomInt`，但**不能由它存在就声称降临一定调用此安全随机源**。本轮未对所有真实客户端/服务端调用者或已部署版本进行全链验证。

从算法推断：只要每步随机索引合法且覆盖剩余池所有索引，任一固定大小的四子集合**条件可达**。若额外假设每步在剩余N枚中独立均匀采样，则N≥4时每个四子无序集合概率为 `1/C(N,4)`；本次NP黑方15枚均合格时是`1/1365`。**这不是实测频率，也不是产品批准的概率参数**。没有证明实际抽签序列可从玩家存档复现。

「随机可注入」不等于「自然对局可完整重放」：精确复演至少需要固定进入降临前的权威状态、候选ID数组顺序、实现版本、每次 `randomInt(pool.length)` 的返回索引或足以确定这些返回值的可验证随机源状态；本轮尚未找到授鳞专用的真实抽签记录、种子/回放标识与公私信息边界验收。测试可用特定索引序列构造条件分支，但不得把构造当自然对局中已真实抽中，更不能泄露本应私有的信息。

## 3. NP合同AS / AP / ES的更新判定

源合同：`worklines/standard/specs/NP_H02_M04_H21_AS_AP_ES_CONTRACT_20261020.json`。开局为标准32棋，B1–B4祈求，R5完整反制，B5开始降临；在这条条件前缀下，黑方15枚非将帅仍存活受黑方控制，且在棋盘上。程序所写 `min(4,15)` 恰选四且不放回，因此合同中的「黑马有鳞／黑卒无鳞」和反向集合都能够由**覆盖所有下标的合法随机输入**产生。

| 分支 | 合同里的条件授鳞 | 当前证据所能确认 |
|---|---|---|
| AS | 黑马有鳞、路径黑卒无鳞 | 条件集合在实现的随机抽样空间内可达；受鳞结果下原子末态仍仅来源/合同推演 |
| AP | 路径黑卒有鳞、黑马无鳞 | 同上；不涉及发动当回合的重复审批 |
| ES | 黑马有鳞、路径黑卒无鳞 | 同上；已用刺杀机会不退款沿既有限定 |

这些条件性可达性为**V2源码核对加V1推论**，不是一次实际随机运行，更不是自然棋谱、原子裁判或王安全完成验收。NP既有合同保留 `not_claimed_reachable_by_actual_rng` 原字段的历史证据意义，不偷偷把旧UNRUN改成PASS；如需修订，应另提交最小契约差分并经相应执行证据复验。

## 4. 空池、小池、顺序、重复与误用防护

- **0枚**：不调用索引随机、无棋获鳞；不能因为降临执行过就虚构4个授鳞对象。
- **1–3枚**：现代码全选，一枚ID最多一次；规则字面「最多四」并不足以单独证明全选是新已批玩法。
- **4枚**：现代码全选四枚、仅顺序随机；若只关心集合，集合确定。
- **5枚及以上**：现代码四次无放回按剩余数组索引抽取，不是可重复命中同棋的带放回四抽，也非玩家手选。
- **控制/河道/身份**：取B5当时的权威控制方和棋盘在场池，不把离盘河道旧坐标充作候选；不以秘密真帅寄宿身份额外暴露给客户端。
- **随机合法性前提**：`choose` 本身未像初始暗子洗牌一样显式校验注入函数的整数边界；测试/记录必须保证 `0 <= randomInt(m) < m` 且为整数。异常注入不作为玩法新概率。
- **代码所在层级**：引擎PR13尚未合并，本次定位的源行为不得冒充main已上线版本或全部终端同版实测。
