## 可复现缺陷：换轨之后错误标记棋盘 `(0,0)`

在已公开的合成中局中，通过真实页面处理器执行 `(0,6)` 与 `(2,6)` 两棋交换，棋子实际位置正确更新；随后：

- `src/hero-actions.ts:336` 通用主技能结束处把没有 `command.to` 的技能记为 `lastMove.from = lastMove.to = {x: 0, y: 0}`，`landed:false`。
- `web/app.ts:2719`、`:2720` 的 `renderBoard` 直接按上述 from/to 添加 `last-from`、`last-to`，没有识别本技能的双端移置。实际技能选择处理器在 `web/app.ts:3965` 起。
- 最终 DOM 为 `(0,0)` 同时具有 `last-from last-to`；两个真实端点不是这一标记的来源。

这是一项可见的行动反馈错误，不是技能成功与否或已证实的引擎胜负漏洞。本轮未发现需要推翻本英雄自主设计或等待共享未知结果协议的具体引擎缺陷。修复可由试点在自己的引擎分支完成；主线只需发布具体任务，无须用户重新设计参数。

建议修复须表达“双体移置”或清晰的专属技能行动反馈，不能把本次行动伪装成单棋普通走子来凑 `from/to`。可利用 `src/hero-pilot.ts:58`、`:59` 现有 `relay_swap` 自动事件中的实际端点，或作最小的英雄专属显示处理；显示样式由执行者自主选择。保留稳定落位顺序、H05 资格边界、H06 完整快照、默认棋局和试验门禁。验证成功交换后的实际端点／标签，并覆盖失败、重复命令不产生伪反馈和既有普通行动标记。
