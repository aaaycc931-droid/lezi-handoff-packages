# UI保真修改

执行用户于2026-10-13明确授权长期沿用的规则。读取 [references/policy.md](references/policy.md) 中的语义边界和验收要求；不要要求用户每次重新提醒。

## 执行顺序

1. 恢复当前批准版本、原始母版、源图层、未确认候选和本次修改范围。核对文件身份、尺寸及摘要；不要以文件名或审批JSON代替实际看图。
2. 区分首次探索生成、局部精修、源资产提取、重建、生产接入。首次新UI可以生成候选；已有批准部分默认进入保真编辑。
3. 固定不可覆盖的母版，保存无字背景、字体/图标/按钮等独立图层和布局参数。优先修改可编辑源资产或源图层，再合成预览。
4. 从固定母版与当前已批准图层/参数重新合成每个版本。保留所有已批准差分；不要把反复修改的扁平图当成全图再生成、压缩或缩放的输入，也不要为了回到母版丢弃后续批准的修改。
5. 只改变指定区域及其必要抗锯齿边缘。保留未指定背景、纸纹、色彩、边框、图标、布局、内容和尺寸。已批准组件须原样提取，不要重新画一套冒充拆层。
6. 字体替换优先使用有明确来源与许可的真实字库/字形，独立渲染后等比合成；遵循本项目批准字体，不擅自换字库、合成笔画或拉伸字形。不要把某项目字体推广到其他项目。
7. 没有无字背景时，先说明旧字遮挡像素不可精确恢复。只在必要旧字遮挡及边缘范围做一次局部估计，并保存恢复后的底层供后续使用；不要逐轮抹字、修补。不要以亮度阈值把山水、边框等深色背景误识别为文字。无法安全分离时登记限制，并提出取得源层或单独审批重建的路径。
8. 保留原分辨率和比例，保存无损PNG或原生可编辑格式。不要以整体锐化、提亮、拉伸、放大或有损转码掩盖局部修改。
9. 对明确要求保留像素的栅格预览，用 `scripts/verify_pixel_diff.py` 比较批准基线与候选；另核对不可变母版SHA-256。任何保护区域像素变化必须说明并修复，不能自动放宽范围。比较图层/矢量/响应式代码时采用适合其表示的结构差分及固定条件渲染对照，不虚称像素完全相同。
10. 实际查看成图和关键细节，检查新字准确性、可读性、残字、补底痕迹、边缘、遮挡、清晰度与颜色。区域外变化为0不证明区域内质量合格。
11. 保存原版、候选、源层、参数和验证记录。一次展示一张实际待审图，说明真实差分；用户明确批准后才更新当前批准指针。静态批准、动效、运行、设备验收和生产接入分别记录。

## 权限与停止条件

- 将用户当前明确修改授权作为具体差分依据；已批准部分仍受保护。
- 不把局部修改自动扩展成全页重设计、全项目风格统一、生产代码接入、部署或发布。
- 工具只能全图重绘、源层缺失会导致明显偏差、或像素检查失败时，先说明具体限制和可逆替代，再请求必要的扩大授权。用户已有授权时不要重复请求。
- 新生成内容若必须用图像生成工具，按相关工具规则执行；局部结果只作为新图层使用，保护其他区域。不要用整页再生成替代原资产保留。
- 不保证未来模型必然执行正确；以来源、实际产物和验证结果为准。

## 验证命令

```bash
python scripts/verify_pixel_diff.py approved.png candidate.png --regions regions.json --out verification.json
```

`regions.json` 格式为 `{"regions":[{"id":"title","x":20,"y":30,"width":200,"height":80}]}`，坐标是原图像素。只列真实授权区域，禁止为通过检查而扩大到整页。矩形范围内部也有受保护背景时，追加 `--mask allowed-mask.png`，使用原尺寸二值蒙版（白色允许改动、黑色保护）；允许区是矩形与蒙版的交集，不能只靠矩形检查。用 `--expected-source-sha256` 核对已登记批准摘要；没有登记摘要时如实标记未核对历史身份。脚本比较解码后的8位RGBA及色彩配置，不代表编码字节相同，遇高位深格式须用保留该精度的验证方式。

记录 `source_version`、母版与候选摘要、修改区域、差分像素数、区域外差分、母版是否不变、补底是否估计、实际视觉检查、批准状态及下一断点。不要把本规则保存操作写成当前图稿已批准。
