# UI与主线接口/权限边界

UI应消费产品的公开状态及当前玩家授权私有视图。主线研究适配器original_jieqi_P0_v0.1不是UI的数据API，也不是其他模式的放行凭证。不得读取PolicySession.room、权威暗池、种子、未来随机带或private_evidence来驱动界面。

| 信息 | 允许显示 | UI验收要求 |
| --- | --- | --- |
| 已公开棋盘、行动方、权威倒计时 | 按当前玩家视图 | 不用动画本地推算正式回合；覆盖层不暂停常规时钟 |
| 未揭示暗子真实身份 | 仅已有明确授权的本人知识 | 对手界面与公开日志不可出现身份/真实阵营旁路 |
| 陷阱秘密位置/叠层 | 拥有者授权范围 | 本机交接前清除上一玩家秘密标记 |
| 【秘密】技能次数/冷却/目标 | 仅拥有者 | 对手按钮亮暗、提示、动画、日志不泄露实际使用 |
| 【洞察】本人历史知识 | 本人授权记录 | 洗牌后区分曾知信息和失效位置约束；不把历史当当前槽位事实 |
| 当前已消灭记录 | 权威公开分组 | 隐藏阵营独立组，不借归组提前泄露；复活/回溯正确更新 |
| 模式、英雄与畸变可用性 | 权威目录及featuresReady | UI不能绕过新模式保护，也不能自定未确认适配 |
| 正式评分和研究参数 | 不作为玩家产品展示 | 冻结数值不渲染成0或“已评分” |

共享需求记录字段：request_id、页面/状态、适用模式、观察者角色、字段名/类型/现有来源、公开/本人秘密/权威、触发时序、最小接口差分、缺失时呈现、所需主线决策与证据。UI设计状态分支与真实API支持分别标注。

时间/秘密字段设计须先画最小时间轴并核对权威回调。例如原揭棋H11的A/B窗口与B替代回合不同于普通开始；不得由UI自行多播放一次黑方开始、重新发资源或提前刷新。半混乱/普通模式时序必须分别核验。

原型验收应包括相同公开/本人授权输入、不同未授权秘密的成对屏幕/DOM对照；私有动作目标不能使对方按钮、日志、计时或网络状态提示产生旁路。此项是未来验收计划，本次没有执行。
